# Deliverable learning summaries

> **FICTIONAL RECONSTRUCTION — AI-created illustrative account based on the team description, project artefacts and COMP2300 specification. It represents a simulated project scenario, not independently verified historical evidence. Review and personalise before any formal use.**

## D2

We learned that the strongest conceptual differentiator was not a dashboard but
the trust checkpoint between quantity, factor and feasible action. This changed
the prototype from an estimate-first flow to a universal result with assumptions,
unavailable and shared-boundary routes.

## D3

We learned that a credible evaluation plan needs operational sample rules,
materials and analysis fields, not just a method label. The protocol now separates
completion, critical error, help and comprehension.

## D4

We learned that a thin vertical slice exposes more architectural truth than a
wide feature list. The application isolates a calculation/persistence path and
retains unsupported categories descriptively.

## D5

We learned that action advice must be a reversible decision state and that CO2,
CO2E and unavailable records require separate summaries. This changed totals and
action wording.

## D6

We learned that a release candidate is a package plus guide, test evidence and
failure recovery, not only compiled classes. Scrollable forms, explicit labels and
release gates were added.

## D7

We learned that analysis discipline is part of product integrity: an empty or
malformed dataset must remain visibly incomplete. The analyser rejects impossible
rows and reports `not_conducted` for the blank template.
